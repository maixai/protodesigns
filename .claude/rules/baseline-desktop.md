# baseline-desktop:`targets` 含 `desktop` 时适用

叠加在 [`protodesign-baseline.md`](./protodesign-baseline.md)(跨端共享基线)之上。

**桌面端与 Web 端共用同一份载体代码**(见共享基线第 ④ 节),区别只在**外层是浏览器还是桌面壳**。因此本基线关注的是"壳带来的额外要求",而不是另起一套 UI。

> ⚠️ 桌面壳的渲染引擎与浏览器**不是同一个**:不同平台的系统 WebView 版本与实现有差异,字体度量、原生控件外观、部分 CSS 特性可能不同。原型在 Chrome 里好看 ≠ 打包后一样好看。涉及"打包后才暴露"的问题,见第 ④ 节。

## ① 窗口语义(不是设备断点)

桌面窗口是**用户可自由拖拽的连续尺寸**,不是固定断点:

| 项 | 要求 |
| --- | --- |
| 最小尺寸 | 明确定义窗口**最小可用尺寸**(默认基准 `800×600`),并在该尺寸下不破版 |
| 连续缩放 | 在最小尺寸到最大化之间连续拖拽,布局不跳变、不溢出 |
| 最大尺寸 | 超宽屏下内容设最大宽度并居中 |
| 窗口状态 | 位置 / 尺寸 / 最大化状态应可持久化(生产实现;原型期用 mock 演示) |

## ② 壳能力清单(原型期用 mock 演示,生产期替换实现)

以下能力**原型期必须以 mock 形式可演示**,否则评审无法验证;生产期由 Electron IPC 提供实现,UI 零改动。

| 能力 | 原型期 mock 形态 |
| --- | --- |
| 原生菜单栏 | 页面内渲染一段模拟菜单栏,分组固定为 App / File / Edit / View / Window / Help |
| 全局 / 应用快捷键 | 可触发,并在界面上有可见反馈 |
| 托盘图标 | 可演示菜单项 |
| 右键 / 上下文菜单 | 真实弹出 |
| 拖放 | 文件拖入的视觉反馈 |
| 文件对话框 | 返回固定的假路径 |
| 系统通知 | 可演示 |
| 深浅色跟随系统 | 用 `prefers-color-scheme` 读取,深浅两套 token 都可用 |
| 单实例锁 | 可演示"再次启动聚焦已有窗口" |
| 文件关联 / 深链 | 可演示入口 |
| 自动更新的交互 | 下载进度 / 重启提示的界面 |

## ③ 视觉细节

| 项 | 要求 |
| --- | --- |
| DPI / 缩放 | 在 100% 与 200% 缩放下均不破版 |
| 深色模式 | 深色下**所有**界面可读,不允许"白卡片压在深色背景上" |
| 字体回退 | 不依赖某个平台独有字体;中英文混排不出现方框或错位 |
| 窗口控制区 | 不自绘遮挡系统窗口按钮(交通灯 / 最小化最大化) |

## ④ 打包后才会暴露的问题(生产验收装置的职责)

以下问题**原型装置测不到**,必须由打包后的真机验收覆盖:

- 系统 WebView 的字体度量差异导致的换行 / 布局位移;
- 原生对话框、系统权限;
- IPC 调用的真实失败(路径无权限、文件被占用);
- 原生菜单项是否真的存在;
- 窗口尺寸持久化是否真的生效。

> 详见 `protodesign` Skill 的"生产验收装置"一节;原型期只保证设计基线,不宣称已覆盖上述问题。

## ⑤ 验收清单(桌面追加项)

- [ ] **最小尺寸**:`800×600` 下不破版。
- [ ] **连续缩放**:拖拽窗口从最小到最大化,无跳变 / 溢出。
- [ ] **壳能力可演示**:菜单栏、快捷键、右键菜单、深色跟随、窗口尺寸至少四样在原型里能演示。
- [ ] **深色可读**:深色模式下无不可读区域。
- [ ] **DPI**:100% / 200% 缩放下不破版。
