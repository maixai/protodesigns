# baseline-mobile:`targets` 含 `mobile` 时适用

叠加在 [`protodesign-baseline.md`](./protodesign-baseline.md)(跨端共享基线)之上。

## ① 定位差异(与 web / desktop 的关键区别)

**移动端是另一套 UI 范式**,不与 web / desktop 共用载体代码:

- 载具是 **Flutter(Dart)**,不是 Vue;
- 没有 hover、没有窗口、没有菜单栏;
- 主体信息架构**复用 web 原型的定稿**,本原型只做**平台特有的差异部分**。

> 移动原型的性质也与 web 侧不同:Flutter 没有"原型 → 迁移"这一步,**这份原型就是生产代码的草稿**,而不是一次性交付物。因此本基线对代码质量的要求与生产同级。

## ② 平台语义清单

| 维度 | 要求 |
| --- | --- |
| 安全区 | 所有页面用 `SafeArea` / `MediaQuery` 处理刘海、圆角、home indicator,内容不被遮挡 |
| 手势返回 | iOS 侧滑返回可用;Android 返回键 / 手势可用 |
| 软键盘 | 输入框获得焦点时键盘弹起,**不遮挡当前输入框**;表单可滚动到可见位置 |
| 底部导航 | Tab 数量 3-5 个;底部元素避开 home indicator |
| 动态字体 | 跟随系统字号放大后不破版、不截断 |
| 横竖屏 | 主要页面在横屏下仍可用(或显式锁定方向并说明理由) |
| 权限 | **按需、在上下文里申请**,不启动时一次性全弹;先给价值再要非关键权限 |
| 系统通知 | 与权限分开处理,通知的展示与点击可演示 |
| 中断与生命周期 | 来电 / 切后台 / 通知中断后恢复,状态不丢 |
| 触觉反馈 | 关键操作(长按、开关、错误)有触觉反馈 |
| 深链 | 外部链接 / Universal Link 可进入指定页面 |
| 无障碍 | VoiceOver / TalkBack 可朗读,可聚焦顺序合理 |

## ③ 交互态调整(覆盖共享基线第 ⑥ 节)

触屏**没有 hover**,共享基线的 hover 项在移动端不适用:

| 状态 | 移动端要求 |
| --- | --- |
| hover | **不适用**;但原型的桌面版本仍适用 |
| pressed | 必须有按压反馈(涟漪 / 缩放 / 变色) |
| focus | 仍要求(外接键盘 / 无障碍场景) |
| disabled | 视觉禁用 + 不可点击 |

> **判定原则**:任何依赖 hover 才能看出的信息或反馈,必须同时存在一个**非 hover 的等价可见状态**,否则在触屏上等于不存在。

## ④ 设计 token 在 Flutter 的落地

设计语言的 token 取值同样适用(完整定义与 Flutter 落地见 [`design-language.md`](./design-language.md) 第 ⑩ 节),落地方式不同:

- 集中定义在 `lib/theme/` 的 `ThemeData` / `ThemeExtension`,**禁止在 widget 内 hardcode 颜色、字号、间距**;
- 深浅两套主题都要提供。

## ⑤ 视觉校准(与 web 侧的差异)

Flutter 的渲染一致性比 WebView 好得多,但仍有天然差异,校准时必须知道:

| 项 | 说明 |
| --- | --- |
| 字体 | 默认按平台选字体(iOS / Android 不同),要跨端一致须**打包自带字体**;否则换行位置会有差异 |
| 滚动物理 | 默认按平台切换(iOS 回弹 / Android 钳制),要统一须覆写 `ScrollBehavior` |
| 转场与图标 | 默认按平台切换,要统一须固定 `PageTransitionsTheme` 与显式图标 |
| 文字栅格化 | 桌面与移动的渲染路径不同,即使同字体也非逐像素一致 |

**验收分层**:

| 层次 | 手段 | 命令 |
| --- | --- | --- |
| 日常迭代 | `flutter run -d chrome`(浏览器里看布局与视觉,快) | `make run` |
| 静态分析 | `flutter analyze` | `make calibrate` |
| 组件视觉回归 | golden 测试(像素比对) | `make calibrate` |
| **平台特有交互验收** | **模拟器 / 真机**(手势、键盘、安全区、权限 —— 浏览器里假不出来) | 手工 |

> 浏览器只能验"长什么样",验不了"手感对不对"。手势返回、软键盘、安全区、权限弹窗**必须上真机或模拟器**。

**golden 基线的已知限制(务必知道)**:

- **默认情况下跨 OS 是稳定的**:Flutter 测试环境**不加载** app 的自定义字体,文字渲染为等宽的
  `FlutterTest` 方块 —— 这等价于 Alchemist 的 "CI 模式",所以普通 `matchesGoldenFile` 的基线可以
  直接跨 OS 比对,**不需要额外引入 Alchemist**。
- **一旦加载真实字体,基线就与 OS 绑定**:字体栅格化与抗锯齿不同,同一张图在 macOS / Linux 之间会
  差 1-2px,跨 OS 用同一份基线必然假失败。此时才需要 Alchemist —— 用它出一套跨 OS 稳定的方块基线,
  真实字形的美学审查留在本地。
- 无论哪种,都要**固定视口尺寸与 devicePixelRatio**,并**等异步数据落定再截图**,否则基线会随机漂移。
- golden 只证明"看起来没变",不证明"算对了";业务逻辑正确性靠单测覆盖。

## ⑥ 验收清单(移动追加项)

- [ ] **安全区**:刘海 / 圆角 / home indicator 区域无内容被遮挡。
- [ ] **手势返回**:可用。
- [ ] **键盘**:输入框不被键盘遮挡。
- [ ] **底部导航**:Tab 3-5 个,避开 home indicator。
- [ ] **动态字体**:放大系统字号后不破版。
- [ ] **权限时机**:按需申请,不在启动时一次性全弹。
- [ ] **pressed 反馈**:所有可点元素有按压反馈。
- [ ] **无 hover 依赖**:不存在"只有 hover 才能看到"的信息或反馈。
- [ ] **深色可读**:深色主题下所有界面可读。
- [ ] **真机验证**:平台特有交互已在模拟器 / 真机确认,不只依赖浏览器预览。
